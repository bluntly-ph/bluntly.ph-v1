# Product CSV import

Admin → Products → **Import** (Administrator or Super Admin). Upload a CSV, read the
preview, decide what to do with rows that match an existing product, then import.
Nothing is written until you import, and the import writes **everything or nothing**.

Code: `backend/app/services/product_admin_service.py` (`COLUMNS`, `REQUIRED`, `EXAMPLE`
are the source of this page), `POST /api/v1/admin/products/import`,
`GET /api/v1/admin/products/import/template`, `components/admin/products/ProductImportModal.tsx`.
Tests: `backend/tests/test_product_import_csv.py`, `backend/tests/test_product_admin_add_import.py`,
`tests/frontend/product-import-model.test.mjs`.

## The file

- UTF-8 CSV (Excel: *CSV UTF-8*), at most **500** products and **1 MB**.
- Row 1 names the columns. Any order. Headers are matched ignoring case and surrounding
  spaces; a space or a hyphen reads as `_` (`Source URL` = `source_url`). `listing_url` is
  read as `source_url`.
- A column may appear once (a repeated column refuses the file).
- **Unknown columns** are not read; the preview lists them under "Not read".
- **Blank rows** are skipped. A blank cell is "not given".
- The **Download the template** link is generated by the API from the same columns, with
  one example row.

## Columns

| Header | Required | Type | Example | Meaning | Validation | Normalization |
|---|---|---|---|---|---|---|
| `brand` | **yes** | text ≤ 120 | `Jisulife` | Brand, the first part of the canonical name | non-blank | trimmed |
| `line` | **yes** | text ≤ 120 | `Handheld Fan` | Product line / series (`products.line`) | non-blank | trimmed |
| `category` | **yes** | slug | `home-appliances` | Catalogue category | one of `audio`, `automotive`, `beauty`, `electronics-tech`, `fashion-accessories`, `food`, `gaming`, `health-fitness`, `home-appliances`, `home-living`, `kids-toys`, `office-productivity`, `sports-outdoors`, `pets` (also `electronics`, `tech` → `electronics-tech`) | lowercased; alias resolved |
| `variant` | no | text ≤ 120 | `Life 9` | Key spec / variant, part of the name (`products.key_spec`) | — | trimmed |
| `type` | no | text ≤ 120 | `Desk` | Descriptor, last part of the name (`products.descriptor`) | — | trimmed |
| `aliases` | no | list | `jisulife fan \| life9` | Other names search should find | each ≤ 160 | split on `\|`, trimmed, blanks dropped, duplicates and the product's own name skipped |
| `source_url` | no | URL | `https://shopee.ph/…-i.1.2` | The product's marketplace listing | `http(s)://` web link | a Shopee / Lazada / Amazon link also becomes the product's first **listing** (platform read from the host); duplicates are found ignoring `www.`, query, fragment and trailing `/` |
| `specs` | no | list of pairs | `Battery: 4000 mAh \| Weight: 160 g` | The Edit modal's specs | each item `Label: Value` | split on `\|` then on the first `:`; a value never joins the name from a file (switch "In name" in Edit) |

The canonical name is built exactly as Edit builds it: `brand line variant type`.

**Not columns, on purpose:**

- **Image.** Every catalogue image lives in Supabase Storage (`product-images`); the
  platform never fetches a URL (owner decision "no scraping, ever", `docs/MILESTONES.md`,
  2026-07-15). Add photos after the import with Edit → photo. A hotlinked image would
  also make the catalogue depend on someone else's server.
- **Platform.** Read from the listing link's host, so it can never disagree with the link.
- **External product ID / model number / product id.** The product model has no such
  column; the listing link is the marketplace identity.

## What the preview says about each row

| Outcome | Meaning | On import |
|---|---|---|
| **New** | No product has this listing or this name | created (canonical, named, specs, aliases, listing) |
| **Matches a product** | The catalogue already has it — by its listing (as the product's link or one of its listings), by its exact name (case, spacing and punctuation aside), or both | **Skip** (default), or **Attach**: the row's listing becomes another listing of that product and the row's name and aliases become aliases. The product's name, category, specs and photo never change. Offered only when there is something to add |
| **Repeated in file** | Same name or listing as an earlier row | skipped |
| **Conflict** | The listing belongs to one product and the name to another, or the listing is on two products | never written — fix the row, or merge the products in Products first |
| **Can't import** | A required cell is missing, an unknown category, a bad link, a spec without `Label: Value`… (row number + reason) | skipped |

Matching is `app/services/product_matching.py` — the same exact keys every submission
goes through; near-matches ("Life 9" vs "Life 9 Pro") stay two products.

## Import

- The server re-reads the file and re-checks every row against the catalogue as it is at
  that moment; a row you chose to attach that no longer matches (or has nothing to add) is
  not attached. The client's preview is never trusted.
- New and attached rows are written in **one transaction**. If any row fails to save,
  nothing is written; the failing rows say *Failed* with the reason.
- The summary: **total, added, attached, skipped, can't import, failed**.
- One **Activity log** entry (`product_import`): who, when, the file name, the counts and
  the new products' ids. The file itself is not kept. Attached listings and aliases are
  also logged on the product (`listing_attach`, `alias_add`).

## Permissions

Administrator and Super Admin (`require_staff`). Members and store owners get 403; signed
out 401 — preview, import and template alike.
